Présentation du projet

SmartCleanCity est une plateforme numérique complète conçue pour moderniser et optimiser la gestion des déchets urbains. Elle connecte trois catégories d'acteurs — administrateurs municipaux, agents de collecte terrain et citoyens — dans un écosystème digital unifié, couvrant l'intégralité du cycle de gestion des ordures : de la détection du remplissage d'un bac à la validation de la collecte, en passant par la planification intelligente des tournées.

Développée en 2025-2026, l'application répond aux enjeux spécifiques des villes africaines confrontées à une croissance urbaine rapide, un manque de digitalisation des processus terrain et une insuffisance dans la traçabilité des opérations de collecte.

Objectifs principaux

  • Réduire le taux de bacs non collectés grâce au monitoring IoT en temps réel
  • Optimiser les trajets des camions via l'algorithme Dijkstra + amélioration 2-opt
  • Améliorer la transparence des opérations avec un tableau de bord analytique
  • Permettre aux citoyens de signaler les dépôts sauvages avec géolocalisation et photos
  • Centraliser la gestion des équipes, véhicules, zones et performances
  • Générer automatiquement les primes d'équipes selon les collectes effectuées

3.4 Navigation GPS et optimisation des itinéraires

C'est le module le plus complexe de l'application. Il combine géolocalisation temps réel, algorithmes de graphes et WebSockets pour offrir une navigation terrain professionnelle.

1. Démarrage de tournéeL'agent ouvre sa tournée depuis /agent/tournee/:id, clique "Démarrer la navigation" → redirection vers /agent/navigation/:id.

Algorithmes d'optimisation

L'optimisation des itinéraires est le cœur algorithmique de SmartCleanCity. Elle est implémentée entièrement en JavaScript natif dans backend/services/dijkstra.service.js, sans dépendance externe.

5.1 Distance Haversine

Formule de calcul de distance géographique entre deux points GPS. Utilisée dans tous les algorithmes d'optimisation.

Entrées: lat1, lon1, lat2, lon2 (degrés décimaux)
Rayon terrestre: R = 6 371 km
dLat = (lat2 - lat1) × π/180
dLon = (lon2 - lon1) × π/180
a    = sin²(dLat/2) + cos(lat1) × cos(lat2) × sin²(dLon/2)
dist = R × 2 × atan2(√a, √(1-a))
Sortie: Distance en km (précision: ±5m)
Complexité: O(1)

5.2 Min-Heap (File de priorité)

Structure de données fondamentale pour Dijkstra, permettant d'extraire en O(log n) le nœud de coût minimum.

Opérations:
  push(priority, value) — Insertion + remontée (bubble-up)   : O(log n)
  pop()                 — Extraction min + descente (sink-down): O(log n)

Implémentation: Tableau indexé avec parent à (i-1)>>1, enfants à 2i+1 et 2i+2
Avantage vs tableau trié: O(log n) insertion vs O(n)

5.3 Graphe K plus proches voisins

Construction d'un graphe sparse pour éviter la complexité O(n²) d'un graphe complet.

Entrée: nodes = [{id, latitude, longitude}], K = 6
Pour chaque nœud A:
  1. Calculer distance Haversine vers tous les autres nœuds
  2. Trier par distance croissante
  3. Conserver les K plus proches
  4. Ajouter arêtes bidirectionnelles pondérées A↔Bi
Sortie: graph = { nodeId: [{neighborId, weight(km)}] }
Complexité: O(n² log n)   — acceptable pour n < 500 bacs

5.4 Algorithme de Dijkstra

Chemin le plus court entre la position courante du camion et le prochain bac cible.

Entrée: graph, startId, endId
Initialisation: dist[all] = ∞, dist[start] = 0, heap.push(0, start)

Boucle (while heap non vide):
  (d, cur) ← heap.pop()
  Si cur déjà visité → ignorer
  Marquer cur comme visité
  Si cur == end → sortir (chemin trouvé)
  Pour chaque voisin non visité:
    nd = d + poids(cur, voisin)
    Si nd < dist[voisin]:
      dist[voisin] = nd
      prev[voisin] = cur
      heap.push(nd, voisin)

Reconstruction: chemin ← remonter prev depuis endId jusqu'à startId (inverser)
Sortie: { path: [id1, id2, ...], totalDistance: km }
Complexité: O((V + E) log V) ≈ O(n log n) pour graphe K-NN

5.5 Heuristique Nearest-Neighbor (Greedy)

Ordonnancement initial des bacs par approche gloutonne. Phase 1 de optimizeMultiStop().

Entrée: startPoint {lat, lng}, bacs[], criterium
Fonction coût selon criterium:
  'distance' : dist = haversine(cur, bac)
  'temps'    : dist / 30 km/h × 60 (minutes)
  'priorité' : dist × (1 - niveauRemplissage/100)

Algorithme:
  pool = copie(bacs), ordered = [], pos = startPoint
  Tant que pool non vide:
    Calculer coût(pos, bac) pour chaque bac ∈ pool
    Sélectionner bac* avec coût minimum
    ordered.append(bac*) ; pool.remove(bac*) ; pos = bac*
  Retourner ordered

Complexité: O(n²)

5.6 Amélioration 2-opt

Optimisation locale post-greedy. Réduit typiquement la distance de 10 à 20% sur des instances réelles. Activé pour les critères distance et temps (pas priorité, car pondération non-linéaire).

Entrée: route = [bac0, bac1, ..., bacN] (résultat nearest-neighbor)
Condition: len(route) ≥ 4 et criterium ∈ {distance, temps}

Boucle externe (tant qu'amélioration):
  improved = false
  Pour i de 0 à n-2:
    Pour j de i+2 à n-2:
      // Arêtes actuelles:  (i→i+1) + (j→j+1)
      d_avant = haversine(route[i], route[i+1]) + haversine(route[j], route[j+1])
      // Arêtes inversées:  (i→j) + (i+1→j+1)
      d_après = haversine(route[i], route[j])   + haversine(route[i+1], route[j+1])

      Si d_après < d_avant - ε:          // ε = 1e-10 (tolérance flottant)
        Inverser segment route[i+1..j]   // swap in-place
        improved = true

Complexité: O(n² × itérations) — converge en 2-5 passes pour n < 200

5.7 Suppression des outliers géographiques

Protection contre les données de test aberrantes (bacs créés avec coordonnées (0,0) ou hors zone). Appliquée avant tout calcul d'optimisation.

Algorithme:
1. Calculer centroïde C = (Σlat/n, Σlng/n)
2. Calculer distance di = haversine(C, bac_i) pour chaque bac
3. Trier les distances → trouver la médiane m
4. Seuil adaptatif: t = clamp(m × 10, 30km, 150km)
5. Garder bacs avec di ≤ t
6. Garde-fou: si aucun bac gardé → prendre les 5 plus proches de C

Cas couverts: bac(0,0) Gulf of Guinea, bac en Europe, saisie inversée lat/lng
